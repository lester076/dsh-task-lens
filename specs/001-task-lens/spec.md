# 功能规格：Task Lens

**功能分支**：`main`（初始 MVP，功能编号 001）  
**创建日期**：2026-11-17  
**状态**：已明确，可实施  
**输入**：为 DSH 长任务提供 AI 拆解进度、子任务小窗问答和显式会话分支。

## 用户场景与测试

### 用户故事 1 — 看见真实任务进度（P1）

用户提交多步骤任务后，AI 创建结构化计划。用户随时看到总完成数、当前步骤及各项状态，而不必从流式文字中猜测。

**优先级原因**：这是插件的核心价值，其他功能可在此基础上独立增加。  
**独立测试**：建立四项计划，依次开始并完成两项，断言进度为 2/4、50% 和第三项进行中。

**验收场景**：
1. **Given** 无计划，**When** AI 创建合法计划，**Then** 出现有序子任务与 0% 进度。
2. **Given** 一个进行中子任务，**When** AI 报告完成并启动下一项，**Then** 完成数和当前项原子更新。
3. **Given** 失败子任务，**When** 显示整体进度，**Then** 失败不计完成且可见失败原因。
4. **Given** 已持久化计划，**When** 重放 Session 事件，**Then** 恢复最后 revision 的相同状态。
5. **Given** 简短任务或无任务，**When** 没有计划事件，**Then** 不渲染占位进度条。

### 用户故事 2 — 在小窗理解单个子任务（P2）

用户点击当前或任意子任务，在右侧或浮动小窗提问，不影响主代理执行。

**优先级原因**：解决“知道做到哪，但不知道如何做”的追问需求。  
**独立测试**：对所选任务发送“怎么测试”，收到流式答案，主 Session 的任务 revision、消息数与运行状态均不因此改变。

**验收场景**：
1. **Given** 已显示任务，**When** 点击“怎么做”，**Then** 小窗包含该任务上下文并流式显示回复。
2. **Given** 小窗已打开，**When** 用户切换任务或提问，**Then** 回复只进入正确的会话/任务/小窗历史。
3. **Given** 请求失败或取消，**When** 用户重试，**Then** 保留问题且不出现重复回答。
4. **Given** 小窗问答，**When** 请求模型，**Then** 仅包含有界只读上下文且不包含执行工具。
5. **Given** 小窗在右栏，**When** 使用原生浮窗操作，**Then** 移动不创建 Session 分支。

### 用户故事 3 — 按需提升为会话分支（P3）

用户决定独立探索某子任务时，通过按钮或拖到会话列表，将小窗提升为原生分支。

**优先级原因**：增强深入工作的连续性，但不应干扰前两个核心价值。  
**独立测试**：点击提升或模拟拖放后确认，验证只调用一次源 Session fork；取消和失败不创建分支。

**验收场景**：
1. **Given** 小窗，**When** 点击提升并确认，**Then** 创建继承源会话的分支并打开。
2. **Given** 小窗拖拽到合法会话列表目标，**When** 释放，**Then** 仅显示确认；再次确认才 fork。
3. **Given** fork 失败或权限不足，**When** 操作结束，**Then** 原会话、小窗和草稿不变并显示错误。
4. **Given** 触屏或无拖放环境，**When** 查看小窗，**Then** 仍可使用提升按钮。

## 边界情况

- 空计划、重复标题、未知 taskId、多个进行中、超过 30 项、空标题或超长文本。
- 旧 revision 的延迟回复不得覆盖新计划；重复事件重放必须幂等。
- 任务被修订或计划清除时，已打开小窗保留历史并提示上下文已过期。
- 主代理已停止或无可用模型：显示错误，不伪造活动或完成。
- 小窗连续快速切换、关闭、刷新、断线重连：回答不能跨任务串写。
- 拖放到非本插件目标：无操作；重复 drop/双击：同一个提升动作只能提交一次。
- API 缺失 sessionId、方法错误、请求过大、JSON 非法、未认证：均返回安全错误。

## 功能需求

- **FR-001**：模型必须能创建包含 2–30 个有序子任务的完整计划，每项具有稳定 id、标题、说明、验收标准和可选估算。
- **FR-002**：系统必须通过 Session 事件持久化计划及状态迁移，并以最后写入的完整计划恢复。
- **FR-003**：系统必须拒绝非法状态迁移、未知 id、重复 id、空文本、超限数据和多个进行中任务。
- **FR-004**：UI 必须显示 completed/total、百分比、当前任务和每项文字状态；百分比不得由输出长度推断。
- **FR-005**：用户必须能打开任一子任务的原生右栏面板并浮动/停靠，且此操作不创建分支。
- **FR-006**：小窗必须提供怎么做、预计多久、预期效果、怎么测试四个快捷提问和自由提问。
- **FR-007**：回答必须通过 DSH 当前模型流式生成，支持停止和重试；时间答案必须区分估算与实际状态。
- **FR-008**：小窗上下文必须只读、有界，且不得提供工具或修改主任务。
- **FR-009**：小窗历史必须独立于主会话消息并按 sessionId/taskId 隔离、限制和持久化。
- **FR-010**：只有显式提升确认才可调用原生 Session fork；取消、拖放悬停和普通浮动均不得创建分支。
- **FR-011**：HTTP 接口必须先经 DSH 鉴权，仅访问指定 Session，限制方法、正文和响应大小。
- **FR-012**：界面必须提供中英文、键盘等价操作、加载/空/错误状态及减少动态效果支持。

## 关键实体

- **TaskPlan**：一个会话中的任务计划；含 revision、标题、有序 Subtask、更新时间和来源轮次。
- **Subtask**：稳定 id、标题、说明、验收标准、状态、可选 AI 分钟估算、失败原因及时间戳。
- **FocusThread**：小窗问答；含 id、源 sessionId/taskId/planRevision、消息、模型路由和分支状态。
- **BranchPromotion**：一次显式提升；含源会话、任务、小窗、确认状态、目标分支及错误。
- **SessionContextExcerpt**：只读近期用户/助手消息，包含截断标记，不含凭据和工具执行能力。

## 可衡量结果

- **SC-001**：结构化状态提交后 1 秒内反映到本机 UI。
- **SC-002**：两次操作内打开任一任务小窗；四个核心问题均可一键询问。
- **SC-003**：100% 小窗问答测试不产生主会话消息或任务状态变更。
- **SC-004**：100% 未确认拖放测试不产生分支，非法 API 请求均非 2xx。
- **SC-005**：30 个任务、100 条小窗消息的限制下刷新恢复一致，无无界存储增长。
- **SC-006**：类型检查、自动化测试和构建在干净安装后通过。

## 假设与决策

- 首版仅支持 DSH Web 及其桌面 Web 容器，Node.js 24+。
- “不是新对话”指不是普通 Session/fork；小窗使用独立只读咨询请求，不启动主代理轮次。
- 采用独立结构化工具而不是读取 `todo_write`，因为需要稳定 id、验收标准、说明、失败原因与估算。
- 计划默认顺序执行；并行任务、自动子代理和依赖 DAG 延后。
- 小窗历史作为插件自己的 Session 事件保存，事件来源不属于主模型历史投影。
- 拖放先确认是防止误创建持久会话的有意约束。
- AI 分钟估算是模型提供的参考值，不是根据真实历史训练的预测服务。
