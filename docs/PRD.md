# dsh-task-lens 产品需求文档

**版本**：0.1.0（MVP）  
**日期**：2026-11-17  
**状态**：已批准进入实现  
**目标平台**：DeepSeek Harness（DSH）Web，兼容使用同一 Web 容器的桌面端

## 1. 背景与问题

DSH 能流式输出长任务，但一段包含多个小任务的工作中，用户仍难以回答：整体做到哪一步、当前正在做什么、哪些已完成、某一步如何实施和验证。现有进度通常只是文字叙述，追问又可能打断主任务或污染上下文。

## 2. 产品目标

为长任务提供一条可信、可恢复的子任务进度条，并提供聚焦当前子任务的小窗问答。小窗默认不是新对话分支；用户希望深入探索时，可显式把小窗提升为主会话的分支。

### 成功指标

- AI 建立计划后，用户在 1 秒内看到总进度、当前子任务和任务状态。
- 用户两次操作内打开任意子任务的问答小窗。
- 小窗提供“怎么做 / 预计多久 / 预期效果 / 怎么测试”快捷问题及自由提问。
- 刷新或重启后恢复主任务状态与小窗历史。
- 小窗问答不会推进主任务、修改主对话或创建分支。
- 核心状态机、API 鉴权、构建和类型检查全部通过自动化验证。

## 3. 用户与核心场景

**主要用户**：使用 DSH 执行编码、研究、文档或其他多步骤长任务，希望了解进度并偶尔追问细节的用户。

1. 用户提交长任务，AI 将其拆为 2–30 个可验证子任务。
2. 用户从输入框上方的进度条看到完成数、当前步骤和失败状态。
3. 用户点击某子任务，在右侧或浮动小窗询问实施、时间、效果与测试。
4. 用户继续观察主对话，小窗回答不会干扰主代理。
5. 用户希望独立深入时，将小窗提升为分支；分支继承主会话历史并带有子任务上下文。
6. 用户把小窗拖到左侧会话列表；系统先显示明确放置提示，再由用户确认创建分支。

## 4. 范围

### MVP 包含

- 模型工具：创建/替换计划、开始子任务、完成子任务、失败/重试、清除计划。
- 状态：pending / in_progress / completed / failed / blocked；整体进度按已完成子任务比例计算。
- 进度 UI：输入区上方紧凑进度条、展开任务列表、当前任务突出显示。
- 子任务小窗：右侧栏 tab，支持原生拖动和浮窗；展示任务说明、验收标准、状态和 AI 估算。
- 小窗问答：四个快捷问题、自由文本、流式回答、停止、重试和本地历史。
- 上下文：只读主会话近期消息及所选子任务；不授予小窗工具，不修改主任务。
- 分支：按钮提升；拖拽到会话列表时出现放置目标，释放后弹出确认；调用 DSH 原生 fork。
- 持久化：任务状态写入 Session 事件；小窗历史独立保存，可随插件存储恢复。
- 中英文、键盘操作、错误反馈、请求鉴权、输入及资源上限。

### 不包含

- 自动创建多个执行代理或自动并行实施子任务。
- 根据 token 数、日志长度或动画伪造精确百分比。
- 承诺准确 ETA；无估算时显示“未估算”。
- 小窗直接写文件、运行命令、审批操作或改变主任务状态。
- 自定义嵌套任务树、跨设备同步、团队协作、插件市场发布。
- 劫持 DSH 私有 DOM 来维持核心功能。

## 5. 功能要求

### 5.1 AI 拆解与任务状态

- 长任务开始时，模型通过结构化工具一次性提交完整计划，每项含标题、可选说明、验收标准与可选分钟估算。
- 同一主会话同一轮只保留一个活动计划；替换计划必须生成新 revision。
- 状态变更使用稳定 taskId；未知 id、重复开始、非法迁移和超过上限必须拒绝。
- MVP 默认顺序执行，最多一个 in_progress；completed 可因修订回到 pending，并记录新 revision。
- 完成度 = completed / 总任务数；failed 和 blocked 不自动算完成。
- 新用户轮次开始时不擅自清除旧计划；模型显式替换或用户显式清除。

### 5.2 进度呈现

- 无计划时不占空间；有计划时显示已完成数/总数、当前任务、进度条与展开按钮。
- 每项显示文字状态；失败/阻塞可重试入口由模型处理，UI 不擅自推进。
- 数据从 Session 投影或同源状态读取，多个界面不维护互相矛盾的任务副本。

### 5.3 子任务小窗

- 点击任务打开对应面板；相同会话和任务复用已有 tab。
- 可直接浮动，也可在右侧栏内通过 DSH 原生拖拽浮动/停靠。
- 面板显示任务详情和问答；预置四类快捷问题。
- 回答采用当前会话模型，逐段流式展示；切换子任务不能串写历史。
- 同时每个小窗最多一个回答；关闭面板中止传输但保留已接收内容。
- 模型不可用时保留提问并显示可重试错误。

### 5.4 提升为分支与拖放

- 按钮和拖放是同一“提升”命令的两个入口，均需要明确用户意图。
- 分支继承源会话，标题包含子任务标题；创建后打开分支并发送一条聚焦该子任务的初始上下文。
- 拖放释放只显示确认，不直接创建；取消不产生分支。
- 权限不足、源会话运行中不可 fork、网络失败时显示错误且不重复创建。
- MVP 拖拽使用标准 HTML5 Drag and Drop；触屏使用按钮替代。

## 6. 非功能要求

- 状态更新至可见目标 <1 秒（本机正常负载）。
- 单计划最多 30 项；标题 200 字符、说明 4000、验收标准 4000、单条提问 4000。
- 上下文默认最近 12 条用户/助手消息，总字符上限 24,000；超出使用近期优先截断并标注。
- 单会话小窗历史最多 100 条、每条回答 32,000 字符；不允许无限增长。
- 不增加外部服务或遥测；问答使用 DSH 已配置的模型与凭据。
- 所有插件 HTTP 接口必须通过 DSH 鉴权；请求体最大 64 KiB。

## 7. 同类调研结论

检索了 DSH 官方仓库、awesome-dsh-plugin 目录和公开搜索结果：

- `chen8923/dsh-task-progress`：脚本/命令进度上报、悬浮层与右栏，不负责 AI 子任务问答与分支。
- `stxr/dsh-codex-side`（目录条目）：侧边追问和提升分支，不提供本产品的结构化任务进度。
- DSH 原生 `todo_write`、右侧栏和 Session fork：提供可复用基础，但没有组合成目标体验。
- 其他 ETA/任务板/多代理插件只覆盖局部或面向不同工作流。

**结论**：存在相邻方案，未发现完整同构插件；选择独立实现并优先复用宿主公开能力。详见 `specs/001-task-lens/research.md`。

## 8. 验收标准

1. 创建一个四项计划并完成两项后，显示 50%（2/4），当前项与状态正确。
2. 完成、失败、重试、替换、刷新恢复均符合状态机；非法操作有稳定错误。
3. 小窗四类快捷问题与自由提问均能流式回答；主会话事件和任务 revision 不变。
4. 未授权 API 请求被拒绝；跨会话访问、超限输入、并发冲突不能绕过限制。
5. 提升分支仅在确认后发生；失败不会丢失原会话、小窗或输入。
6. 小窗可在右侧栏和浮窗间移动；拖拽到会话列表有可见确认步骤。
7. 中英文界面无关键硬编码缺失；键盘可完成打开、提问、停止与关闭。
8. 自动化测试、类型检查、构建与打包检查通过；真实 DSH 验证范围如实记录。

## 9. 风险与应对

- **模型不维护状态**：工具描述要求开始即开始、完成即完成；UI 将陈旧状态标为状态而非继续制造活动。
- **超长会话上下文成本**：小窗只取有界近期消息，不复制全部历史。
- **宿主 API 预稳定**：锁定已验证 DSH 版本，集中维护宿主类型适配层。
- **拖放与宿主拖拽冲突**：只接受本插件 MIME，释放后确认，不修改原生会话排序。
- **问答隐含修改预期**：界面与系统指令明确“只读咨询”，不提供工具。

## 10. 发布定义

MVP 交付可安装 npm 包结构、源码、测试、构建产物、Spec Kit 文档、README 与 GitHub 仓库。完成真实 DSH Web 手动验收前标记为 alpha。
